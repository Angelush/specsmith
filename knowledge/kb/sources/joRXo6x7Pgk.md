# Nobody Laid Out The Five Kinds Of Software You Can Make. So I Did.

A beginner-facing map for non-technical personal-software builders: five software "shapes" (local tool, web app, native phone app, background service, hardware project) that determine tool choice almost mechanically (Lovable/Replit/Bolt for hosted builds, Claude Code/Codex + GitHub + Superbase/Vercel for more control), illustrated with a EUR200 Raspberry Pi ferry-tracker and a household maintenance app. The core governance technique is keeping four small text files (project/decisions/scenarios/agents.markdown) so the AI "building partner" has to reveal its choices in plain English rather than making them invisibly. Nate closes by mapping his own Open Brain / Open Skills / Open Engine / Ringer tools onto the same beginner framing.

## Concepts covered

- [[concepts/vibe-coding-phenomenon]] — the five software shapes (local tool, web app, native phone app, background service, hardware project) and the tool routing that follows from each; the four-file "building partner" governance pattern (project/decisions/scenarios/agents.markdown); the plain-English disclosure instruction that keeps a non-technical builder in charge; why no agent self-report substitutes for testing real scenarios on the real device.
- [[concepts/open-brain-systems]] — Nate's own Open Brain / Open Skills / Open Engine / Ringer tool suite reframed in plain language for non-technical builders, each mapped to a distinct problem (what the software knows, how the builder behaves, how work moves, how delegated work is supervised).
